# Finding and sharing project files

Upload a proposal, contract, invoice or design file inside its **journey stage**. **All project files** is a searchable view of those same records and client uploads, organised in journey order. There is no second upload or copy to maintain.

- **Search files** finds a file name, journey stage, file type or version.
- **File type** and **Journey stage** can be combined with search. **Clear filters** restores the full permitted list.
- **Open journey stage** opens that existing stage and moves keyboard focus to it, including in the client portal.
- **Upload a project-wide file** is a secondary option for files with no particular stage. These appear under **Project-wide files**. An unavailable stage association is labelled separately; the library does not guess a replacement.

Owners see a sharing badge and the existing detailed access explanation. **Private draft** is unpublished. **Shared · access locked** means publication is recorded but other checks still block access. **Available to client** means the file meets the current project access rules; it does not prove a client was invited, signed in or downloaded it. The invitation/account state lives in the client access controls.

Clients and read-only previews see only their permitted files. Search and filter options derive from that same permitted list. Final files still require verified approval and payment; unpublished and hidden-stage files stay private. Download routes recheck permissions. Previously issued signed links may work for up to 60 seconds; downloaded copies cannot be recalled.

Ordinary client uploads are labelled **Client upload**. A file with an explicit original-contract reference is labelled **Contract return**, with the original file name when that document is available. Neither label verifies a signature or payment. Review and verify these separately in the journey. Creative approval choices appear for presentations; other files accept comments or revision requests, and previous feedback remains visible.

This update needs no SQL migration. It does not add file types, increase the 3 MB limit, change access rules or provide embedded signing. Hosted acceptance is separate from the automated fictional-service browser checks.
